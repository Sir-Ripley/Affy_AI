## 2024-03-17 - Potential performance bottleneck in encodeBitmapToBase64Png
**Learning:** The `encodeBitmapToBase64Png` function uses `ByteArrayOutputStream`. Creating a new stream without setting an initial capacity causes byte array reallocations under the hood, making it inefficient for large images. Furthermore, `ByteArrayOutputStream().use { ... }` should be used instead of `.let` to ensure streams are correctly closed. A good size estimate for JPEG encoding is `width * height / 4` bytes to avoid reallocations without overly allocating.
**Action:** Optimized `encodeBitmapToBase64Png` by using an initial capacity for `ByteArrayOutputStream` of `width * height / 4` and closing it via `.use {}`.
## 2024-03-17 - Unnecessary use of LinkedList
**Learning:** The `LinkedList` class is used to collect bitmaps and blobs in `sendMessageStream` inside `Chat.kt`. While this isn't a massive performance hit, `ArrayList` (or simply `mutableListOf()` in Kotlin) is generally preferred due to better cache locality and less overhead unless you frequently insert/remove from the middle of the list. Here we just add elements and then iterate over them, making `ArrayList` the superior choice.
**Action:** Replace `LinkedList` with `ArrayList` or `mutableListOf()`.
## 2024-03-17 - Inefficient `toTypedArray()` call in Chat.kt
**Learning:** In `Chat.kt`, the history list is converted to an array using `toTypedArray()` every time a message is sent. This creates a new array every time, copying all elements. If the history grows, this could be a slight performance hit. A better approach is to pass a List to `generateContent` or `generateContentStream` directly. However, the `GenerativeModel` API uses `vararg prompt: Content`. To avoid copying the whole array plus one element, a List based API or spreading `history + prompt` might be used, although `*history.toTypedArray(), prompt` still creates a copy. The most optimal way is to add `prompt` to a list and pass the entire list to `generateContent` that takes an `Iterable` or `List`. So an array must be passed. `(history + prompt).toTypedArray()` or `*(history + prompt).toTypedArray()` might be a little clearer, but performance-wise it still creates an array. So there might not be a huge optimization there without changing the API of GenerativeModel.
